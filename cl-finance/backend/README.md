# CL Finance — защищённая версия (план внедрения)

## Что готово
- `backend/schema.sql`: схема PostgreSQL и Row Level Security для квартир, назначений пользователей, бронирований, расходов, уборок.
- Роли: `admin` (полный доступ к назначенной квартире), `owner` (только чтение отчётов, броней, расходов, уборок), `cleaner` (просмотр только назначенных уборок).
- Финансовые данные **не загружаются** в GitHub. Текущий GitHub Pages — публичная демонстрация, а не защищённый кабинет.

## Важные ограничения
- SQL ещё **не применён** к серверу, база не создана и логин не подключён.
- Не следует вводить настоящие данные в GitHub Pages.
- В таблице уборок пока нет загрузки фотографий. Для них потребуется закрытое хранилище с серверной проверкой доступа.
- Горничной нельзя давать прямой UPDATE всей записи: отдельный серверный endpoint должен проверять её назначение и разрешать менять только статус, комментарий и время завершения.
- В бронированиях намеренно нет имён, телефонов и иных персональных данных гостей.

## Что потребуется для запуска
1. Создать отдельный проект Supabase (PostgreSQL/Auth) и настроить регион хранения по требованиям пользователя и применимому законодательству.
2. Применить `backend/schema.sql` в SQL Editor; проверить RLS тестовыми аккаунтами каждой роли.
3. Создать доверенный backend для приглашений пользователей, выдачи и отзыва прав, а также отметок уборки.
4. Подключить веб-клиент к Supabase Auth и API; сделать отдельные экраны администратора, собственника и горничной.
5. Включить MFA для администратора, резервное копирование, аудит и тесты разграничения прав.
6. Перенести финансовые данные через авторизованный импорт, не сохраняя их в публичном репозитории.

## Правила доступа
| Действие | Администратор | Собственник | Горничная |
|---|---|---|---|
| Просмотр финансов | Да | Только своя квартира | Нет |
| Редактирование финансов | Да | Нет | Нет |
| Просмотр бронирований | Да | Только своя квартира | Нет |
| Просмотр уборок | Да | Только своя квартира | Только назначенные |
| Завершение уборки | Да | Нет | Через проверяемый backend |
| Управление пользователями | Через backend | Нет | Нет |

**Ограничение GitHub Pages:** нельзя обеспечить приватный доступ одной только скрытой кнопкой или JavaScript-переключателем роли.
